Creator Scorecard

Two channels can have the same subscriber count and be completely different buys. This works out which is which, live, from public data.

Stays in this browser. Never sent anywhere but Google. Get a free key, it takes about ten minutes.

What the numbers mean

  • Median views. The middle of the last 30, so one runaway hit can't drag the number up. Roughly what a sponsored video would reach.
  • Views as % of subs. Whether the audience still turns up. A huge subscriber count with thin views means those people signed up years ago and left.
  • Engagement rate. Likes plus comments over views. Do people react, or just watch?
  • Days between uploads. How active the channel is, and how predictable.
  • View spread. Standard deviation as a percentage of the mean. At 38% every video lands in roughly the same band, so a placement has a floor. At 79% the median is propped up by the occasional breakout and one placement is a gamble.

How it works

Three calls per creator. Find the channel, list its recent uploads, then fetch the statistics for all 30 videos in one go. Costs 3 quota units. A free key gets 10,000 a day, so you'd have to look up 3,000 creators before it stopped. Asking for each video separately would cost 32 units for the same answer. The page does the maths itself: no server, no database, no build step.

Why Twitch isn't on this page

Twitch won't take a key. You swap a client ID and secret for an access token, then send that token as a Bearer header on every call. The secret is the problem. This page is public, so anything in it is public, and a public secret is no use to anyone. Twitch runs on the command line instead, where the credentials stay on my machine.

A key is a password you keep sending. A token gets issued to you and expires. That's the real reason products have a backend, and it took building both to see it.

Both platforms, one table

A YouTube subscriber and a Twitch follower aren't the same thing, so putting them in one table means deciding what the merged number means. Here each platform fills in what it can and says why the rest is blank. Nothing gets estimated.

What is missing, and why:
  Twitch. Followers: Twitch only gives a follower count to a token the
     creator has personally authorised, so an app token cannot see it.
  Twitch. Engagement rate: past broadcasts carry no public likes or
     comments, so there is nothing to divide by views.

Real output, 10 September 2026. Static here, for the reason above.

Both blanks are real. Twitch will only give a follower count to a token the creator authorised themselves, and past broadcasts carry no likes or comments to count. That's why companies buy creator data rather than collecting it. The fields worth having need permission you haven't got.

The key sitting in this page

You can read it. So can anyone. Hiding a key in a web page isn't possible, so this one is restricted instead: in the Google Cloud console it's tied to one website by HTTP referrer, and to the YouTube Data API alone. A browser on any other site gets a 403. I tested that from an empty referrer and from another domain.

That stops a browser, not a person. Send the right Referer header by hand and the key works, which I also tested. So this is a speed bump rather than a lock. The worst case is someone spending the free daily quota, and nothing beyond it, because the key can only reach one API. Put a bill on the other end and it would have to live on a server the browser never sees.
