Creator Scorecard

Score a YouTube creator the way a brand would, from public data. Two channels can share a subscriber count and be completely different buys.

Kept in this browser only, never sent anywhere but Google. Get a free key, it takes about ten minutes.

What the numbers mean

  • Median views is the middle value of the sample, not the average, so one viral hit does not flatter the channel. It is what a sponsored video would realistically reach.
  • Views as % of subs shows whether the audience still turns up, or the subscriber number is history.
  • Engagement rate is likes plus comments over views, averaged. Whether people react or just watch.
  • Days between uploads is the span of the sample divided by the gaps in it.
  • View spread is the standard deviation of views as a percentage of the mean. Low means every video lands about the same. High means the channel lives on the odd breakout, and any single placement is a gamble.

How it works

Three calls to the YouTube Data API for each creator: one to find the channel, one to list its recent uploads, one to fetch those videos' statistics. That is 3 quota units of the 10,000 a free key gets per day. No server, no database, no build step. The page does the arithmetic itself.

Why Twitch is not on this page

There is a second half to this project, and it cannot run in a browser. Twitch does not accept a key. It makes you swap a client ID and secret for a short-lived access token, then send that token as a Bearer header. A browser page is public, so a secret in one is not a secret. Twitch therefore lives in the command line version, where the credentials stay on the machine.

What the command line version does with both

Two platforms do not describe a creator the same way, so they cannot be merged without deciding what the merged thing means. A YouTube subscriber is not a Twitch follower. The rule is that each platform fills the fields it can and states the rest, with the reason attached. Nothing is estimated to fill a hole.

What is missing, and why:
  Twitch. Followers: Twitch only gives a follower count to a token the
     creator has personally authorised, so an app token cannot see it.
  Twitch. Engagement rate: past broadcasts carry no public likes or
     comments, so there is nothing to divide by views.

Real output, run on 10 September 2026. Not live on this page, because of the secret.

Those two holes are not bugs. They are the reason companies buy creator data instead of collecting it: the fields worth having need either the creator's permission or a provider who already holds them.

About the key in a browser page

Anything a browser page holds, a visitor can read, so a key shipped in the page is a key given away. The fix is not to hide it but to restrict it: in the Google Cloud console an API key can be limited to one website by HTTP referrer, and to one API. A copied key then does nothing from anywhere else. That is why this page can be public.

It is a limit, not a lock. Referrers can be forged, so the honest ceiling is that a determined person could spend the free daily quota. For anything with a bill attached, the key belongs on a server the browser never sees.
